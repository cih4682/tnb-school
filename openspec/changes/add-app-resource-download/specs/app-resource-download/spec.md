## ADDED Requirements

### Requirement: 관리자 자료 업로드
관리자는 앱 관리 화면에서 특정 앱에 파일을 하나 이상 업로드할 수 있어야 한다. 업로드된 파일은 비공개 Storage 버킷에 저장되고, 파일명·설명·용량 등 메타데이터는 `resources` 테이블에 기록된다.

#### Scenario: 관리자가 앱에 파일을 업로드
- **WHEN** 관리자 권한을 가진 사용자가 앱 수정 화면의 "첨부 자료" 섹션에서 파일을 선택해 업로드한다
- **THEN** 파일이 `resources` Storage 버킷에 저장되고, 해당 앱과 연결된 `resources` 레코드가 생성되어 목록에 즉시 표시된다

#### Scenario: 관리자가 아닌 사용자의 업로드 시도 차단
- **WHEN** 관리자 권한이 없는 로그인 사용자 또는 비로그인 사용자가 업로드 API/쿼리를 직접 호출한다
- **THEN** RLS 정책에 의해 쓰기 요청이 거부된다

### Requirement: 관리자 자료 삭제
관리자는 앱에 첨부된 자료를 목록에서 삭제할 수 있어야 한다.

#### Scenario: 관리자가 첨부 자료를 삭제
- **WHEN** 관리자가 앱 수정 화면의 첨부 자료 목록에서 삭제 버튼을 누른다
- **THEN** 해당 `resources` 레코드가 삭제되고 목록에서 즉시 사라진다

### Requirement: 로그인 사용자의 자료 다운로드
로그인한 사용자는 앱 상세 화면에서 해당 앱에 첨부된 자료 목록을 보고 개별 파일을 다운로드할 수 있어야 한다.

#### Scenario: 로그인 사용자가 첨부 자료를 다운로드
- **WHEN** 로그인한 사용자가 첨부 자료가 있는 앱의 상세 모달을 열고 특정 파일의 다운로드 버튼을 누른다
- **THEN** 시스템은 서명된 다운로드 URL을 발급하고, 사용자는 해당 파일을 받을 수 있다

#### Scenario: 첨부 자료가 없는 앱
- **WHEN** 사용자가 첨부 자료가 없는 앱의 상세 모달을 연다
- **THEN** "첨부 자료" 섹션 자체가 표시되지 않는다

### Requirement: 비로그인 사용자의 다운로드 제한
로그인하지 않은 사용자는 첨부 자료를 다운로드할 수 없고, 로그인을 유도하는 안내를 보게 된다.

#### Scenario: 비로그인 사용자가 첨부 자료가 있는 앱 상세를 연다
- **WHEN** 로그인하지 않은 사용자가 첨부 자료가 있는 앱의 상세 모달을 연다
- **THEN** 각 자료 항목에 다운로드 버튼 대신 로그인 안내(및 로그인 페이지로 이동하는 링크)가 표시된다

#### Scenario: 비로그인 사용자의 다운로드 요청 차단
- **WHEN** 비로그인 사용자가 서명된 URL 발급을 직접 요청한다
- **THEN** Storage RLS 정책에 의해 요청이 거부된다
